# ローマ字入力による日本語名の絞り込み

## 背景

インタラクティブ選択（skim）のマッチ対象は現在 `"ピカチュウ → Pikachu"` という表示文字列（`src/interactive.rs:96`）である。
そのため英名と綴りが近いポケモンはローマ字入力でも絞り込めるが、日本語名と英名が無関係なもの
（フシギダネ / Bulbasaur、ヒトカゲ / Charmander など）は `fushigidane` と打っても候補に出ない。

カタカナ由来のローマ字でマッチできるようにする。

## スコープ

**対象**: インタラクティブ選択（skim）の絞り込み入力のみ。

**対象外**: CLI 引数（`poke-lookup fushigi`）。`SearchService::search_partial` はカタカナのみを対象としたまま変更しない。

この結果、ローマ字が効くのは引数なしで `poke-lookup` を起動したとき（`select_from_all` 経由）である。
`poke-lookup fushigi` は候補 0 件になる。これは意図した制約であり、必要になった時点で別途検討する。

## アーキテクチャ

新規モジュール `src/romaji.rs` を追加する。公開 API は 1 関数のみ。

```rust
/// カタカナ名から、マッチ用のローマ字表記を返す（ヘボン式・訓令式、重複除去済み）
pub fn variants(katakana: &str) -> Vec<String>
```

- 依存クレートの追加なし
- `names.json` のスキーマ変更なし（`ja` フィールドから実行時に導出するため、`schema_version` は 1 のまま）
- 呼び出し元は `src/interactive.rs` の `PokemonItem` 生成箇所のみ
- `src/search.rs` / `src/models.rs` / `src/main.rs` は無変更

## ローマ字生成

カタカナを先頭から最長一致で切り出し、拗音（キャ・シュ・チョ 等の 2 文字）→ 単カナ（1 文字）の順に変換表を引く。

特殊処理は 3 つ。

| 文字 | 処理 | 例 |
| --- | --- | --- |
| ッ（促音） | 次の音の子音を重ねる | バッフロン → `baffuron` / `bahhuron` |
| ー（長音） | 直前の母音を重ねる | ブースター → `buusutaa` |
| ン（撥音） | 常に `n` | サンダー → `sandaa` |

外来音も変換表に含める: ファ / フィ / フェ / フォ、ウィ / ウェ、ヴ、ティ / ディ / トゥ、シェ / ジェ / チェ。
（ファイヤー、ウィンディ等が実データに存在するため）

### 生成する表記

**ヘボン式と訓令式の 2 通り**を生成し、両者が一致する場合は 1 件に重複除去する。

| | ヘボン式 | 訓令式 |
| --- | --- | --- |
| シ | shi | si |
| チ | chi | ti |
| ツ | tsu | tu |
| フ | fu | hu |
| ジ | ji | zi |
| シャ / シュ / ショ | sha / shu / sho | sya / syu / syo |
| チャ / チュ / チョ | cha / chu / cho | tya / tyu / tyo |
| ジャ / ジュ / ジョ | ja / ju / jo | zya / zyu / zyo |

例: フシギダネ → `["fushigidane", "husigidane"]`、ピカチュウ → `["pikachuu", "pikatyuu"]`、
ヒトカゲ → `["hitokage"]`（両式が一致するため 1 件）

### 長音省略形を生成しない理由

`busuta`（ブースター）や `pikachu`（ピカチュウ）のような長音を省いた入力は、**別途生成しない**。
skim のマッチはファジー（部分列）マッチであり、`busuta` は `buusutaa` の部分列、
`pikachu` は `pikachuu` の部分列であるため、そのままヒットする。

一方 `husigi` は `fushigi` の部分列にならない（`h` が `u` より後ろにしか現れない）ため、訓令式の生成は必要である。

この切り分けにより、音節ごとの全組み合わせを取る（＝組み合わせ爆発する）実装を避ける。
1 エントリあたりの生成数は最大 2 件で固定される。

## skim への組み込み

`PokemonItem` に `romaji: String` フィールドを追加する。`variants()` の結果をスペース区切りで連結して保持する。

`SkimItem` の実装を次のように調整する。

| メソッド | 返す値 | 用途 |
| --- | --- | --- |
| `text()` | `"フシギダネ → Bulbasaur fushigidane husigidane"` | マッチ対象 |
| `display()` | `"フシギダネ → Bulbasaur"` | 一覧表示 |
| `output()` | `"Bulbasaur"` | 確定時の返り値 |

### display() のハイライト補正

`display()` に渡される `DisplayContext.matches` のハイライト位置は `text()`（ローマ字を含む）上の位置である。
表示文字列は可視部のみなので、位置を可視部の文字数でクリップしてから `AnsiString::new_str` に渡し直す。

- `Matches::CharIndices` — 可視部の文字数以上の index を除外する
- `Matches::CharRange` — 終端を可視部の文字数でクリップし、開始が範囲外なら空にする
- `Matches::ByteRange` — skim 本体（`lib.rs:169`）と同様に文字位置へ変換してから上記と同じ扱いにする
- `Matches::None` — フラグメントなし

結果として、日本語名・英名に当たったハイライトは従来どおり表示され、隠しローマ字に当たった分だけ表示されない。

### output() による選択結果の取得

現在 `src/interactive.rs:137-141` は選択結果の表示文字列を `" → "` で分割して英名を取り出している。
`output()` を実装することでこのパースを削除し、`item.output()` から英名を直接取得する。

表示書式の変更で壊れる箇所が 1 つ減る。今回変更する範囲内の改善であり、これ以上のリファクタリングは行わない。

## エラー処理

`variants()` は失敗しない。変換表にないコードポイント（想定外の文字）はそのまま出力に通す。
ローマ字が生成できなくても日本語名・英名でのマッチは従来どおり機能するため、フォールバック経路は不要である。

## テスト

**`src/romaji.rs`** — テーブル駆動のユニットテスト

- 単カナ、拗音、促音（ッ）、長音（ー）、撥音（ン）、外来音の各変換
- ヘボン式・訓令式で差が出るケース（フシギダネ）と出ないケース（ヒトカゲ、後者は 1 件に重複除去される）
- 変換表にない文字がそのまま通ること

**`src/interactive.rs`**

- `text()` にローマ字が含まれること
- `display()` にローマ字が含まれないこと
- `output()` が英名を返すこと
- 既存テストは `PokemonItem` の構築が変わるため追随修正する

## 性能

エントリ数は 1000 件程度、1 件あたり最大 2 表記の生成で、`PokemonItem` 構築時に一度だけ実行される。
実測が必要なほどの負荷ではない。
